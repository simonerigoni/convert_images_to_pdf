# AGENTS.md — Project Rules for convert_images_to_pdf

This file contains conventions and instructions for AI coding assistants (Grok, Claude, etc.) working in this repository. It is automatically loaded and takes precedence over higher-level rules.

## Core Principles
- Keep the tool minimal, dependency-light, and focused on its single purpose: reliably convert an ordered list of images into a multi-page PDF.
- Prefer changes that maintain the "run from anywhere" exe experience for end users.
- All quality gates (lint, format, types, tests) must pass locally and in CI before changes are considered complete.

## Environment & Package Management
- **Always use `uv`** for Python environments, dependencies, and running tools. Do not use bare `pip` for project work.
- Local first-time setup (Windows): run `.\my_scripts\Set-Up.ps1`.
- The virtual environment lives at `.venv/` (Windows: `.venv\Scripts\`, Linux/macOS: `.venv/bin/`).
- Activate manually when needed: `.venv\Scripts\Activate.ps1` (PowerShell).
- `uv sync` keeps the environment in sync with `pyproject.toml` + `uv.lock`.
- Cleanup (when needed): `.\my_scripts\Clean-Up.ps1` deletes only the `.venv`.

## Quality & Tooling (Local)
Run these before committing or asking for review:

```powershell
# Full pre-commit suite (recommended)
pre-commit run --all-files -v

# Or individual tools via uv
uv run ruff check --fix .
uv run ruff format .
uv run pyright .
uv run pytest -v --durations=0 --cov --cov-report=markdown:COVERAGE.md
```

- Ruff configuration lives in `pyproject.toml` (line-length = 100, target-version = "py311").
- Pyright is configured for Python 3.11 against the `.venv`.
- Pre-commit also enforces `uv lock --locked` and runs the full pytest + coverage step (writes `COVERAGE.md`).
- The local pytest hook in `.pre-commit-config.yaml` references the Windows `.venv\Scripts\pytest.exe` path — keep this in sync if the hook definition changes.

## Continuous Integration (GitHub Actions)
CI runs on every push (Ubuntu-latest):

1. `uv lock --locked`
2. `uvx ruff check .`
3. `uvx ruff format --check .`
4. `uv run pyright .`
5. `uv run pytest -v --durations=0 --cov --cov-report=markdown:COVERAGE.md`

- The composite action `.github/actions/setup/action.yml` installs uv via `astral-sh/setup-uv`.
- CI is Linux-only. Local development and deployment scripts are Windows/PowerShell-oriented. When making cross-platform changes, verify both environments.
- Coverage report is regenerated by CI and committed as `COVERAGE.md`.

## Coding Style
- Follow ruff + ruff-format rules (run the formatters; do not hand-format).
- 4-space indentation.
- Maximum line length: 100 characters.
- Keep the main `convert_images_to_pdf.py` simple and stdlib + Pillow only.
- Use clear, actionable error messages. Improve the current broad `except Exception` when touching error paths.
- When adding CLI features, introduce `argparse` (or a small dependency like `typer` only if justified). Update the usage example in README and docstrings.
- Add or update tests in `tests/` for any new behavior. The current test suite is minimal (dummy only) — expand it when modifying core logic.
- Type hints are welcome where they improve clarity or help pyright; the project is not fully typed yet.
- Update `COVERAGE.md` expectations only via the configured pytest-cov command.

## Building the Executable
- Primary build command: `deploy.cmd` (runs `pyinstaller --onefile -c "convert_images_to_pdf.py"` then copies the exe to the Python 3.11 Scripts directory).
- The `.spec` file is committed but also listed in `.gitignore` (historical). Regenerate via PyInstaller when needed.
- **Never commit** `build/` or `dist/` directories (enforced by `.gitignore`).
- After building, manually test the produced `convert_images_to_pdf.exe` from an arbitrary folder with real images.
- The delivered experience: user drops the exe anywhere and runs `convert_images_to_pdf.exe img1.jpg img2.png ...` → `merge.pdf` appears in the same folder.

## File & Directory Conventions
- `convert_images_to_pdf.py` — single source of truth for the conversion logic.
- `my_scripts/` — Windows PowerShell helpers (Set-Up, Clean-Up, Config). Source `Config.ps1` pattern is intentional.
- `data/` — sample images and `DATA.md`.
- `tests/` — pytest tests (expand here).
- `.github/workflows/ci.yml` and `.github/actions/setup/` — CI definition. Keep in sync with local pre-commit.
- Output artifacts (PDFs, build products) are intentionally not tracked.

## Git, Commits & Pull Requests
- Use conventional commit messages when possible (e.g., `feat:`, `fix:`, `chore:`, `docs:`).
- Run the full local quality suite (pre-commit + pytest + pyright) before pushing.
- CI is the source of truth — a passing CI run is required.
- Small, reviewable changes are preferred. Update `TODO.md` and this `AGENTS.md` when conventions evolve.
- `.gitignore` already covers caches, venvs, build outputs, and coverage artifacts.

## Windows / PowerShell Specific Notes
- Many user-facing and developer scripts are written for PowerShell and `cmd`.
- Use `$env:`, `Test-Path`, `winget`, and the `Refresh-Path` / `Test-Command` helpers from `Config.ps1` when extending setup scripts.
- Document any new Windows-only or cross-platform gotchas in the relevant script or README.
- The final exe target is a Windows console app.
